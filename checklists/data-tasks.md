# 데이터 과제 체크리스트 (데이터를 다루는 과제일 때만)

사람이 보는 문서입니다. 에이전트는 읽지 않습니다. 과제 안내와 담당자 답변이 항상 우선입니다.
결과는 근거표(`templates/VERIFY.md` 틀)의 상태 열에 **확인함 / 미검증 / 실패 / 미확인**으로 남깁니다.

## 먼저 관찰하기 (표 형태 자료)
```bash
node kit/tools/profile-csv.mjs {파일.csv} --key {키 열 이름}
```
- `profile-csv`는 **관찰만** 합니다: 행 수, 열 개수가 다른 행, 완전 중복, 열별 빈 값·고유 값, 키 반복, 표기만 다른 값 묶음. 오류 판정이나 수정은 하지 않습니다.
- `[구조 경고]`가 나오면 그 결과를 믿지 말고 원본을 직접 확인합니다.
- 관찰된 것이 정상인지(예: 같은 키의 재측정, 이력 행)는 담당자에게 확인합니다.

## 1. 파일·키·조인
- [ ] 파일별 행·열 수, 열 이름과 타입, 날짜 형식·시간대, 단위를 확인했다
- [ ] 키 후보의 고유 여부를 확인했다 (`--key`로 반복 횟수 확인). 중복 키가 정상인지 확인했다
- [ ] 파일 간 연결 키를 정하고 **조인 전후 행 수**를 비교했다 (일대다로 불어나지 않았는지, 키가 맞지 않아 빠진 행이 없는지)
- [ ] 표기만 다른 값(대소문자·공백·하이픈·밑줄)을 같은 대상으로 볼지 담당자에게 확인했다

## 2. 결측·이상값
- [ ] 결측 개수·비율과 **위치**(열, 기간, 제품·라인 같은 그룹)를 확인했다
- [ ] 결측·이상값이 특정 그룹에 **몰려 있는지** 확인했다 (몰려 있으면 삭제가 그 그룹을 통째로 빼 버린다)
- [ ] 읽을 수 없는 행(형식 오류)과 측정 실패(비었거나 0 이하)와 정상 값 0을 구분했다
- [ ] 제거·대체·표시 중 처리 방식을 일괄로 정하지 않고, 담당자 확인이나 "확인 전 가정"으로 남겼다
- [ ] 처리 방식에 따라 결론이 달라지는지 비교했다 (유지 / 제외 / 대체)

## 3. 지표 정의
- [ ] 지표마다 **분자·분모·단위·기간·집계 단위·필터**를 글로 적었다
- [ ] 그룹별 표본 수를 함께 봤다 (표본이 적은 그룹의 비율을 과신하지 않기)
- [ ] 분모가 0이거나 비는 경우의 표시를 정했다
- [ ] 시간대 기준(예: UTC → KST)과 경계값(이상/초과)을 확인했다

## 4. 전처리 전후
- [ ] 원본은 수정하지 않고 처리 결과는 별도 파일이나 출력으로 만들었다
- [ ] 처리 전 건수 → 후 건수와 **제외 사유별 건수**를 기록했다
- [ ] 핵심 지표가 처리 전후로 얼마나 바뀌었는지 기록했다

## 5. 핵심 수치 재계산
- [ ] 핵심 수치를 **다른 방법**으로 다시 계산해 일치를 확인했다 (코드 두 방식, 집계 방식 변경, 작은 표본 직접 계산)
- [ ] 표·그래프·본문의 숫자가 서로 같다
- [ ] 계산에 쓴 명령이나 식을 근거표의 "구현·계산 위치"에 적었다

## 6. 사실·계산·가설·미확인 구분
- [ ] 문서·자료로 확인한 것은 **사실**, 재현 가능한 식으로 얻은 것은 **계산 결과**로 쓴다
- [ ] 그럴듯하지만 직접 확인하지 못한 것은 **가설**, 자료가 없어 알 수 없는 것은 **미확인**으로 쓴다
- [ ] 상관관계를 원인으로 단정하지 않았다
- [ ] 데이터에 없는 설명을 사실처럼 쓰지 않았다
