# 제출 전 체크리스트

사람이 보는 문서입니다. 에이전트는 읽지 않습니다. 과제 안내가 항상 우선입니다.

## 요구·제출물
- [ ] 과제가 요구한 파일이 정해진 경로·이름·형식으로 모두 있고, 심볼릭 링크가 아닌 실제 파일이다
- [ ] 제출 문서가 마지막 변경까지 반영되어 있다(중간에 시험이 중단돼도 제출 가능한 상태)
- [ ] (개선 과제) 기준선과 새 결과를 같은 입력·조건으로 비교한 표가 있고, 나빠진 지표도 적혀 있다
- [ ] 내가 설명할 수 없는 파일·기능·문서는 빼거나 줄였다
- [ ] 요구별 확인표에 확인함 / 미검증 / 실패가 정직하게 적혀 있다
- [ ] 테스트 통과와 요구 충족을 구분해서 적었다
- [ ] 실행 가이드가 실제로 따라 해서 되는 명령만 담고 있다
- [ ] 문서에 쓴 것이 실제 코드·커밋·실행 결과와 일치한다 (근거표의 구현·계산 위치 열 확인)

## 데이터·결과
- [ ] 핵심 수치를 코드나 다른 방법으로 다시 계산해 일치를 확인했다
- [ ] 표·화면의 숫자와 본문 숫자가 같다
- [ ] 단위·날짜·시간대 기준이 결과에 밝혀져 있다
- [ ] 요구에 없는 개인정보·사번이 노출되지 않았고, 비밀값이 없다
- [ ] (웹) 화면 확인표의 항목을 내가 직접 눌러 확인했고, 확인하지 않은 것은 "미검증"이다
- [ ] (비개발형) 주장마다 출처가 있고, 자료에 없는 내용은 "확인 필요"나 "추정"으로 표시했다

## 기록
- [ ] 사용한 외부 자료(키트 URL·커밋 ID)를 기록했다
- [ ] 선택 이유와 고려한 대안이 문서에 있다
- [ ] 남은 한계와 알려진 문제를 숨기지 않았다
- [ ] (커밋을 한 경우) 검증한 변경만 파일을 골라 커밋했고 `kit/`과 원본 데이터는 제외했다

## 제출 (종료 10분 전에 시작)
1. 에디터 탭의 저장 상태를 확인한다
2. "제출하고 문제풀기" → 제출 미리보기에서 파일 목록·크기를 확인한다
3. "제출을 확정하고 문제풀기" — 확정 후에는 파일을 수정할 수 없다
4. 후속 서술형으로 넘어간다 (AI·키트·붙여넣기 불가)

## 마지막 5분
- 가장 중요한 결론·수치가 문서와 결과물에서 같은지 본다.
- 미검증·미구현을 과장하지 않았는지 본다.
