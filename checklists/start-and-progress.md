# 시작·진행 체크리스트

사람이 보는 문서입니다. 에이전트는 읽지 않습니다. 과제 안내가 항상 우선입니다.

## 시작 (0~10분)
- [ ] `git clone` → `sh kit/install.sh check` → 커밋 ID 메모
- [ ] `kit/`을 git에서 제외했거나(`.gitignore` 또는 `.git/info/exclude`) `git add -A`를 쓰지 않기로 했다
- [ ] 과제 README·docs·자료를 끝까지 읽었다 (데이터는 헤더·몇 줄·행 수와 이상 징후 집계)
- [ ] 제출물의 파일 이름·형식·위치, 시간과 도구 제약을 확인했다
- [ ] 요구 / 미확인 / 가정 / 완료 기준을 정리했다
- [ ] (기존 것을 개선하는 과제) 고치기 전에 지표 계산식과 기존 수치(기준선)를 구했고, 내 결과와 규모를 비교할 기준을 정했다
- [ ] (화면 세션을 열 때) 입출력 계약과 담당 파일 표(메인·화면 두 행)를 `WORK.md`에 적었다

## 담당자 질문 (10~30분)
- [ ] 결과 영향이 큰 미확인부터, 실제 값이나 예시를 넣어 한 번에 하나씩 물었다
- [ ] 경계값, 중복의 최종본, 시간대·단위, 누락 값, 불량 데이터 처리, 재실행, 개인정보, 출력 이름을 확인했다
- [ ] "기준 없음"이라는 답은 "미확인"으로 남기고 "확인 전 가정"으로 표시했다
- [ ] 이해한 내용을 정리해 담당자에게 맞는지 확인받았다

## 구현 중
- [ ] 한 요청에 한 요구사항, 프롬프트에 목표·제약·완료 기준·검증이 있다
- [ ] 요구에 없는 기능·추상화·의존성을 추가하지 않았다
- [ ] 원본 데이터를 수정하지 않았다
- [ ] 실행해서 결과를 확인했고, 확인하지 못한 것은 "미검증"으로 적었다
- [ ] 같은 오류로 3번 막히면 수정을 멈추고 가정부터 다시 봤다
- [ ] Codex가 승인 대기이면 확인하고 승인했다
- [ ] (웹) 서버는 `0.0.0.0` + 실제 포트, 서버 터미널 탭은 닫지 않았다
- [ ] 방향이 바뀐 때는 문서의 "의도 갱신"에 적었다

## 중간 점검 (120분 즈음)
- [ ] 진척이 절반 아래면 필수 / 포기로 나누고 범위를 줄였다
- [ ] 남은 시간 기준으로 문서·검증 시간을 남겨 두었다
