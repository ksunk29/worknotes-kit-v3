## 담당 파일·세션 (세션을 둘로 나눌 때)
화면 세션은 `TASK.md`·`WORK.md`를 고치지 않는다. 계약 변경이나 새로 모르는 것은 보고에 적고, 메인이 반영한다.
승인 기준: 계약·업무 규칙·지표·범위 변경과 알고리즘 채택은 응시자가 고른다. 합의된 동작과 다르게 작동하는 버그와 계약을 지키는 내부 수정은 세션이 고친 뒤 회귀 테스트와 함께 보고한다. 같은 실패가 두 번 고쳐지지 않으면 멈추고 보고한다.
| 세션 | 역할 | 수정해도 되는 파일 | 포트·DB |
|---|---|---|---|
| 메인 | 엔진·개선·문서·통합 | | |
| 화면 | 서비스 API·화면(자동 점검을 쓰면 `e2e/` 포함) | | |

## 사람 개입 (AI 제안에 내가 판단을 더한 것)
비교해서 고른 것, 근거를 확인하고 채택한 것, 고치거나 거절한 것, 검증 방법을 바로잡은 것을 적는다. 대화·커밋도 근거가 되지만, 서술형 전에 한눈에 보려고 중요한 것만 여기 모은다. 하지 않은 판단을 했다고 쓰지 않는다.
| 시점 | AI 제안 요지 | 내 판단(비교 후 채택/근거 확인 후 채택/수정/거절/검증 방법 지적) | 바꾼 내용 | 이유 |
|---|---|---|---|---|
