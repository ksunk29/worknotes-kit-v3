# EXPERIMENTS — 실험 기록

> 개선·탐색 과제에서 가설을 하나씩 시험한 기록. 점수 하나보다 "무엇을 해 보니 어땠다"가 남는 것이 목적이다(제출 문서·서술형의 근거). 카드는 **시작할 때** 가설·변경 계획·조건부터 쓰고(끊겨도 남게), 끝나면 결과를 채운다. 과제가 요구한 제출 문서가 있으면 최종 요약을 그 문서에 옮긴다.

## 비교 조건 (모든 실험에서 같게)
- 입력(파일·버전):
- 평가 방법(명령·스크립트, 지표 계산식은 `TASK.md` 기준선 표):
- 시간 제한 / 난수 시드 / 주요 설정:
- 기준선 값(기존 것, 없으면 내가 만든 단순 버전):

## 실험 로그 (한 줄 요약, 카드마다 한 행)
| # | 가설(한 문장) | 변경 요지 | 지표 전 → 후 | 나빠진 지표·요구 위반 | 시간 | 결정 |
|---|---|---|---|---|---|---|
| E1 | | | | | | 채택 / 보류 / 폐기 |

탐색·최적화 과제면 지표 칸에 **상태**를 함께 쓴다: 유효해(제약 위반 0) / 유효해 미발견(시간 안에 못 찾음) / 해 없음(불가능을 증명한 경우만). 최적성을 증명하지 못했으면 "찾은 최선의 해"라고 쓴다. 점수는 독립 검증기로 다시 계산한 값을 쓴다.

## 실험 카드 (가설마다 복사해서 쓴다)
### E1. (제목)
- **가설**: 무엇을 바꾸면 어떤 지표가 왜 나아질 것인가
- **변경**: 파일·함수·버전 플래그(복사본 위치). 기존 결과는 바꾸지 않았다
- **조건**: 입력·시드·시간 제한이 비교 조건과 같은가(다르면 이유)
- **결과**
  | 지표 | 기준선 | 이 실험 | 변화 |
  |---|---|---|---|
  | | | | |
- **나빠진 것**: 나빠진 지표, 요구·제약 위반, 실행 시간 증가
- **왜 그랬나(내 말로)**: 결과가 그렇게 나온 이유에 대한 해석. 확인한 것과 추측을 구분
- **판별 사례**: 기존 방식과 결과가 달라지는 작은 입력 → 손으로 계산한 기대값(테스트 위치)
- **숨은 선택**: 이 변경으로 생기거나 바뀐 선택(가중치, 동점 처리, 기본값, 정렬 기준, 근사, 예외 무시)과 정한 사람(나 / 담당자 / AI 가정)
- **이해 대조**: 반영 전에 내가 먼저 말한 바뀐 함수의 입력·출력·깨지는 입력과, 코드와 대조한 결과(맞음 / 고친 점)
- **결정**: 채택 / 보류 / 폐기 — 이유 한 줄
- **다음 가설**: 이 결과가 알려 주는 다음 시도

## 최종 요약 (동결(145분) 때 채운다, 서술형 "외울 5줄"의 재료)
| 항목 | 내용 |
|---|---|
| 기준선 → 최종 | (지표 값, 같은 입력·조건) |
| 채택한 실험 | (번호와 한 줄) |
| 시도했지만 채택하지 않은 것과 이유 | |
| 가장 효과가 컸던 변경과 그 이유 | |
| 알려진 한계(최적성 보장 여부, 못 해 본 것) | |
