# 정리하고 설명할 준비

1. `WORK.md`(설명 노트 포함), `VERIFY.md`, 실제 변경 파일을 읽고 **실제로 한 일만** 정리한다. 하지 않은 일은 쓰지 않는다.
2. 아래 여섯 가지를 한두 문장씩 적는다.
   - 무엇을 만들었나 (핵심 파일과 동작)
   - 왜 그 방법을 골랐나 (담당자에게 확인한 조건과 연결)
   - 고려했지만 택하지 않은 대안과 이유
   - 에이전트 제안 중 내가 고치거나 쓰지 않은 부분과 이유 (`WORK.md` 사람 개입 표 등 작업 기록에 있는 것만)
   - 어떻게 검증했나 (확인한 것 / 못한 것)
   - 남은 한계와, 시간이 더 있다면 먼저 할 일
3. 핵심 파일 두세 개를 골라 입력·출력·예외와 어떤 입력에서 깨지는지를 소리 내어 설명할 수 있는지 점검한다. 설명이 막히는 부분은 코드를 다시 읽고 필요하면 에이전트에게 설명을 요청해 내 말로 이해한다.
4. 요구에 없는데 만든 기능이나 의존성이 있으면 이유를 설명할 수 있는지, 없다면 빼는 것을 검토한다. 설명할 수 있는 범위를 넘는 산출물과 문서는 줄이는 것을 검토한다.
5. 구조 / 알고리즘 / 데이터 흐름 / 권한 / 실패 대응 / 검증·한계 / AI 협업 일곱 영역마다 질문을 하나씩 받아 먼저 내가 답하고, 그다음 코드와 대조해 틀린 부분과 빠진 부분만 고친다(모의 구술).
6. 과제가 제출 문서의 이름·양식을 요구하면 그에 맞춰 실제 파일로 옮겨 쓴다.

설명 노트는 응시자가 쓴 것이므로 고쳐 쓰지 않고, 코드와 다른 줄만 알린다.

산출물: 위 여섯 가지가 담긴 정리 문서. 후속 서술형은 도구 없이 직접 답해야 하므로 이 정리를 보고 내 말로 말해 본다. 답안 구조는 결론 1문장 → 근거(이유·대안) → 검증 → 한계.

하지 않을 것: 그럴듯하게 보이도록 과장하기, 확인하지 않은 것을 확인했다고 쓰기.
