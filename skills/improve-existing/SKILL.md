# 기존 것 개선: 기준선 → 최소 변경 → 전후 비교

1. **재현**: 기존 것을 먼저 그대로 실행한다. 고치지 않는다. 실행 방법과 출력을 기록한다.
2. **지표 정의**: "나아졌다"의 기준을 계산식으로 쓴다(분자·분모·단위·기간·집계 단위·필터). 용어가 모호하면(예: 탑승률) 둘로 나눠 정의한다. 업무 기준이 없으면 내가 세운 설계 선택이라고 밝힌다.
3. **기준선**: 기존 것의 지표를 같은 식으로 계산해 표로 남긴다. 규모 점검도 한다: 내 결과가 기존 실적과 자릿수가 크게 다르면(예: 3배) 개선을 주장하기 전에 정의·입력·범위가 같은지 확인한다.
4. **회귀 방지**: 기존 출력을 스냅샷으로 저장하거나 현재 동작을 확인하는 테스트를 먼저 만든다. 원본은 수정하지 않는다.
5. **가설 순위**: 개선 후보를 비용·효과로 3개 안쪽으로 줄이고, 한 번에 하나만 시도한다. 시도마다 시간 상한(예: 30분)과 "이만하면 충분"의 기준을 먼저 적는다.
6. **격리된 실험**: 복사본이나 버전 플래그에서 한다. 검증을 통과하기 전에는 메인 결과를 바꾸지 않고, 메인은 늘 실행 가능하게 둔다.
7. **전후 비교**: 같은 입력·같은 조건으로 기준선과 새 결과를 한 표에 놓는다. 좋아진 지표뿐 아니라 나빠진 지표와 요구 위반(누락·중복·제약 위반)도 쓴다. 시간 상한을 넘기면 멈추고 현재까지를 기록한다.
8. 실험은 가설마다 `EXPERIMENTS.md` 카드에 쓴다. 시작할 때 가설·변경 계획·조건을 먼저 적고(끊겨도 남게), 끝나면 결과 표, 나빠진 것, 왜 그랬는지, 채택 여부와 이유, 다음 가설을 채운다. 채택하지 않은 가설과 미검증 한계(전역 최적 아님 등)도 남긴다.

산출물: 지표 정의, 기준선 표, 전후 비교 표, `EXPERIMENTS.md`(가설/결과/채택 여부, 최종 요약). 과제가 요구하는 제출 문서가 있으면 그 안에 쓴다.

하지 않을 것: 기준선 없이 개선 주장하기, 여러 가설을 한꺼번에 바꾸기, 지표만 좋아지고 요구를 어긴 결과를 개선이라 쓰기, 기존 것을 통째로 다시 만들기.
