# 원인 먼저, 수정은 그다음

1. **재현**: 증상을 일으키는 가장 짧은 명령·입력을 찾고, 실제 오류 메시지와 출력을 그대로 기록한다.
2. **좁히기**: 입력 → 처리 → 출력 중 어디서 값이 처음 틀어지는지 확인한다. 필요하면 해당 지점에만 임시 출력을 넣는다.
3. **가설**: "원인은 X, 근거는 Y"를 한 문장으로 쓴다. 근거 없는 추측으로 수정하지 않는다.
4. **최소 수정**: 가설 하나를 확인하는 가장 작은 변경만 한다. 관련 없는 리팩터링은 하지 않는다.
5. **재검증**: 1번과 같은 조건으로 다시 실행해 증상이 사라졌는지, 다른 곳이 깨지지 않았는지 확인한다.
6. 다시 시도하기 전에 "이번 시도는 앞선 시도와 무엇이 다르고, 무엇을 구별하려는가"를 한 문장으로 쓴다. 설명하지 못하거나 같은 문제로 **3번 실패하면** 수정을 멈추고 설계·가정이 맞는지 처음부터 다시 검토하며, 필요하면 사용자에게 방향을 묻는다.

산출물: 원인, 수정 내용, 재검증 결과를 과제 문서(또는 `WORK.md`)에 짧게 기록한다.

하지 않을 것: 원인을 모른 채 여러 곳을 한꺼번에 고치기, 임시 출력을 남긴 채 제출하기.
